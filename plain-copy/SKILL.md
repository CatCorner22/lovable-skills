# Plain copy

Say what the user needs. Use the fewest words that keep the full meaning.

## 1. Find the job
Read the screen and the action behind it. Name the reader, what happened, and what the reader needs to do next. Check real limits, costs, dates, and data use in the app. Flag facts you cannot check.

## 2. Write the text
1. Use simple words, short sentences, and active voice. Put the actor next to the verb.
2. Put the key fact first. Give each sentence 1 job.
3. Name actions: “Save changes”, not “Submit”. Keep the same name through the flow.
4. State errors in 2 parts: what happened and what to do next. Preserve entered data where possible.
5. Explain empty states. Offer the first useful action. Distinguish no records from a failed load.
6. Confirm success with the result and the next step. Match the message to the actual saved state.
7. Explain onboarding at the point of need. Ask for only what the current step needs.
8. Give emails a useful subject, a clear reason, and 1 main action. Keep support and expiry details that matter.

Cut filler, jargon, repeated labels, fake urgency, and claims the app cannot support. Keep warnings, eligibility rules, accessibility labels, refund terms, and privacy facts. Streamline as far as possible without losing content.

## 3. Check in context
Compare old and new text for facts, actors, numbers, conditions, and exceptions. Read buttons beside their headings. Check narrow screens, long names, loading, empty, error, and success states. Keep a useful label for screen readers when you shorten visible text.

Return the revised copy first. List any missing fact or change in meaning. Report which app states you checked and which remain unchecked.
